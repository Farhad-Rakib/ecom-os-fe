# Architecture Variants

| Slug | Label | Notes |
|---|---|---|
| default | Order, Cart & Checkout Management | single architecture — see slipway/product/default/tech-stack.md |
| cart-wishlist-prd | Cart & Wishlist Management | split out from `default` so Cart+Wishlist can ship independently of Checkout/Payment/Shipping/Tax — see slipway/product/cart-wishlist-prd/tech-stack.md |
| order-management-prd | Order Management | split out from `default` so the Order entity/status-lifecycle/admin views can ship independently of Checkout/Payment/Shipping/Tax — see slipway/product/order-management-prd/tech-stack.md |
| store-sync-prd | External Store Sync | new product, not a `default` split — admin control surface (connect/disconnect, status, manual sync) for the already-implemented backend sync engine — see slipway/product/store-sync-prd/tech-stack.md |
| courier-prd | Courier & Delivery Integration | new product — admin control surface (courier CRUD, connection/credentials, dispatch + delivery status on the existing Orders pages) for the backend courier connectors; backend not yet implemented — see slipway/product/courier-prd/tech-stack.md |
| customer-management-prd | Customer Management & Delivery Rating | new product — admin customer directory/status control (Features 1-2, no courier dependency) plus recipient view and delivery rating on the Orders pages (Feature 3, needs `courier-prd` shipped) — see slipway/product/customer-management-prd/tech-stack.md |
| fulfilment-readiness-prd | Fulfilment Readiness | new product, not a `default` split — closes the three unfinished seams on the order lifecycle that stop the platform operating: stock that is never reserved/decremented/restored (`QuantityReserved` is a column nothing writes), cash on delivery (no payment method exists on `Order` at all, so a COD order can never be dispatched), and transactional email to the buyer (`IEmailService` is called only by password reset). Amends `order-management-prd`'s transition rules; consumes `courier-prd`'s delivery record for COD settlement — see slipway/product/fulfilment-readiness-prd/tech-stack.md |
| pos-prd | Point of Sale (In-Store Counter POS) | new product — a till for a tenant's physical shop, selling the same catalog and writing into the same orders, stock ledger and customer records. A register is bound to a `Warehouse` (no new "store" concept); a POS sale IS an order. **Sells offline and syncs later**, which is in deliberate tension with `fulfilment-readiness-prd`'s database-decided stock reservation: an offline register cannot reserve, so oversell across tills is possible by construction and is surfaced as a discrepancy rather than prevented — see slipway/product/pos-prd/tech-stack.md |
